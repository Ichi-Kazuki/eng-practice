# TOEFL ITP演習サイト PRD

## Problem Statement
TOEFL ITPは大学の学内プレースメントテストや交換留学要件として広く使われているにもかかわらず、TOEFL iBT向けのKMF(考満分)のような「大量の演習問題を解ける」学習サイトが存在しない。受験者(特に大学の後輩世代)は、断片的な市販教材や過去問の写しに頼るしかなく、セクション別の反復演習や本番形式での通し演習ができる場が不足している。この結果、学内テストや留学要件突破に向けた効率的な自習が難しくなっている。

## Goals
- 後輩を中心とした学習者が、Structure and Written Expression/Reading各セクションで反復演習できる問題バンクを提供する(v1ではListeningは対象外。音声合成基盤の整備後に追加予定)
- 本番のTOEFL ITPに近い形式・時間制限で模試を通し受験できる体験を提供する
- 間違えた問題を自動的に蓄積し、効率的に復習できる仕組みを提供する
- 正答率からITPスコア目安を算出し、弱点セクション/分野を可視化する
- 個人プロジェクトとして、身近な後輩に実際に使ってもらい、学習の役に立ったという定性的な手応えを得る

## Non-Goals
- **Speaking/Writingセクションへの対応**: TOEFL ITP自体にSpeaking/Writingセクションが存在しないため対象外
- **ETS公式問題の転載**: 著作権リスクを避けるため、公式問題や過去問の丸写しは扱わない(オリジナル問題のみを扱う方針)
- **有料化・法人向け機能**: v1は完全無料の個人プロジェクトのため、決済・サブスクリプション・法人契約管理は範囲外
- **ネイティブモバイルアプリ**: 開発コストを抑えるため、v1はレスポンシブWebのみに限定し、iOS/Androidアプリは作らない
- **多言語UI対応**: 当面は日本語UIのみとし、英語や中国語など多言語対応は行わない

## User Stories

### 学習者(後輩・受験予定の学生)
- As a 受験予定の学生, I want to セクション別(v1: Structure/Reading、将来的にListeningも追加予定)に問題を演習できる so that 苦手分野を集中的に鍛えられる
- As a 受験予定の学生, I want to 本番同様の制限時間で模試を通し受験できる so that 本番の時間配分に慣れることができる
- As a 受験予定の学生, I want to 間違えた問題が自動的に復習ノートに記録される so that 見直しの手間をかけずに弱点を復習できる
- As a 受験予定の学生, I want to 復習ノートから「間違えた問題だけ」を再演習できる so that 効率よく弱点を潰せる
- As a 受験予定の学生, I want to 正答率からITPスコアの目安と弱点セクションを確認できる so that 何を優先して勉強すべきか分かる
- As a 受験予定の学生, I want to 各問題に解説が付いている so that なぜその答えが正しいのか理解できる
- As a 受験予定の学生, I want to 模試の途中で通信が切れても進捗が失われない so that 演習が無駄にならない

### サイト運営者(ユーザー自身)
- As a サイト運営者, I want to 管理画面から新しい問題を追加・編集できる so that 継続的に問題バンクを拡充できる

## Requirements

### Must-Have (P0)
1. **セクション別演習**
   - **決定事項(v1対象セクション)**: v1ではStructure and Written Expression / Reading の2セクションを対象とする。Listeningは音声合成(TTS)基盤の整備コストがかかるため、v1のスコープからは外し、将来追加できるようセクションを疎結合に扱えるデータ設計・UI設計とする(詳細はFuture Considerations参照)
   - セクションごとに問題を絞り込んで演習できる
   - 開始前に問題タイプ・問題数・時間の測り方を設定できる。Grammarは文法補充/誤り指摘/両方、各タイプ5/10/20/30/全問、Readingは5/10/20/30/全問とする
   - タイマーなしでは受験後即座に正誤と解説を表示し、経過時間/制限時間では前後移動と回答変更を許可して提出後に一括採点する
   - 経過時間モードは時間制限なし、制限時間モードはセクションの問題数に応じた既存ペースで自動提出する
   - **決定事項(ログイン要否)**: 「まず触ってもらう」ハードルを下げるため、セクション別演習はログイン不要で利用できる(未ログイン時はCookieで発行する匿名ゲストIDに演習履歴を記録する)。ただしゲストの演習履歴は復習ノート・スコアダッシュボードには表示されない(それらはログインが必要。要件6参照)
   - Acceptance criteria:
     - [ ] ログインしていない状態でもセクション(Structure/Reading)を選択して演習を開始できる
     - [ ] タイマーなしでは解答後、正誤・正解・解説が表示される
     - [ ] 経過時間/制限時間では前後移動・回答変更・未解答提出ができ、提出後に正誤・正解・解説・所要時間が表示される
     - [ ] 制限時間を超えると自動提出され、手動提出と同じ結果画面になる
     - [ ] 同じ問題セットを再度演習できる
     - [ ] 将来Listeningセクションを追加する際、既存のセクション選択UI・データモデルを大きく変更せずに追加できる設計になっている

2. **模試モード(本番形式の通し受験)**
   - v1ではStructure and Written Expression(約25分)・Reading(約55分)の2セクション構成で、制限時間付きの通し受験ができる(Listeningを含む完全な3セクション構成の模試は、Listening追加後の将来フェーズで対応する)
   - Given ユーザーが模試モードを開始した, When 各セクションの制限時間が経過した, Then 自動的に次のセクションへ進む(または模試を終了する)
   - **決定事項(ログイン要否)**: セクション別演習と同様、模試モードもログイン不要で利用できる。進行状態は匿名ゲストID(Cookie)に紐づけてDBに保存するため、ログインの有無にかかわらず通信切断・リロードに耐える
   - **決定事項(固定構成)**: 模試はGrammar40問(文法補充15問・誤り指摘25問、25分)→Reading50問(55分)の固定2セクションとする。開始前に選べるのは「制限時間制」と「経過時間を測る」の2種類だけで、セクション・問題数・タイプは選択させない
   - 公開問題が固定構成の必要数に満たない場合は開始を無効化し、サーバー側でも開始を拒否する
   - Acceptance criteria:
     - [ ] ログインしていない状態でも模試を開始できる
      - [ ] 固定構成(Grammar40問→Reading50問)と時間方式だけが開始前に表示される
     - [ ] 制限時間制ではセクションごとにタイマーが表示され、時間切れで自動的に次に進む/終了する
     - [ ] 「時間を測るだけ」モードでは経過時間が表示され、自動提出は行われない
     - [ ] 通信切断や再読み込みをしても進行中の模試の状態が保持される
     - [ ] 終了後にスコアサマリーが表示される

3. **誤答管理(復習ノート)**
   - 不正解だった問題を自動的にユーザーごとに記録する
   - セクション・日付で絞り込み、誤答のみを再演習できる
   - Acceptance criteria:
     - [ ] 不正解の問題が自動的に復習ノートに追加される
     - [ ] 復習ノートから誤答のみのセットで再演習できる
     - [ ] 再演習で正解した問題は復習ノートから除外(または達成マーク)できる

4. **スコア換算・弱点分析ダッシュボード**
   - 正答率からITPスコア目安(31〜68のセクションスケール得点 → 合計を10倍して平均する方式で310〜677点相当)を算出する
   - **決定事項(換算ロジックのソース)**: ETSの公式換算表は非公開のため、市販対策本・学習サイトなどで広く出回っている非公式の換算表を複数参照し、自分たちでロジックを構築する。特定の単一ソースの丸写しは避け、複数ソースを突き合わせた独自の換算ロジックとする
   - 算出したスコアは「公式スコアではなく、あくまで目安である」ことをUI上で明示する(例: 「予想スコア(目安)」という表記、注記の表示)
   - v1はListeningを含まないため、総合スコア(310〜677点)はStructure and Written Expression / Readingの2セクションのみに基づく暫定目安として算出・表示する。UI上には「Listeningを含まない暫定スコア」である旨を明記し、Listening追加後に3セクション換算へ切り替える
   - セクション別・分野別の正答率を可視化する
   - Acceptance criteria:
     - [ ] 演習・模試の結果からスコア目安が表示される
     - [ ] スコア目安の表示箇所に「公式スコアではない」旨、および「Listeningを含まない暫定スコア」である旨の注記がある
     - [ ] セクション別の正答率がグラフ等で確認できる
     - [ ] 弱点セクション/分野が一目でわかる表示になっている

5. **オリジナル問題データベース**
   - **決定事項(コンテンツ調達方針)**: 問題コンテンツはすべてオリジナルで自作する方針を正式採用する。ETS公式のTOEFL ITP問題・過去問の転載や翻案は一切行わない。ITP形式(出題形式・設問パターン・難易度分布)を参考にしつつ、素材(英文パッセージ・音声スクリプト・設問)はすべて独自に作成する
   - **決定事項(作成方法)**: AIを活用して問題を大量生成し、別のAIによるダブルチェック(正解の妥当性・設問と選択肢の自然さの検証)を経たうえで、最終確認は人間(自分)が行う3段階パイプラインで作成する
   - **決定事項(目標問題数)**: v1リリース時点でStructure and Written Expression 120問 / Reading 150問、合計270問(本番形式の模試3回分をユニークなセットで構成できる分量)を目標とする。Listening 150問分は将来のP2フェーズ(音声合成基盤の整備後)に追加する
   - 著作権リスクを避けつつ、KMFのような大量演習を実現するため、継続的に自作問題を追加できる体制(管理画面からの追加編集、P0要件6の管理画面機能)を前提とする
   - Acceptance criteria:
     - [ ] Structure and Written Expression 120問 / Reading 150問(計270問)が公開されている
     - [ ] 上記問題セットから、時間制限・出題数がITP本番のStructure/Readingパートと同じ模試を最低3回分、問題が重複しない形で構成できる
     - [ ] 全問題がAI生成→AIダブルチェック→人間の最終確認を経て公開されている

6. **最低限のユーザーアカウント機能**
   - 誤答管理・スコア推移を個人ごとに永続的に保存するため、復習ノート・スコアダッシュボードの利用にはログインが必要
   - **決定事項(認証方式)**: Googleログインのみをサポートする。大学生はGoogleアカウント保有率が高く(大学がGoogle Workspaceを利用しているケースも多い)、自前でのパスワード管理・リセットフローの実装が不要になるため、ソロ開発の個人プロジェクトとして実装・セキュリティコストの両面で最も低コストな選択とする。メール/パスワード認証は対象外とする
   - **決定事項(ログイン必須範囲の見直し)**: 当初は全機能にログインを必須としていたが、「まず気軽に問題を解いてもらう」ことを優先し、セクション別演習・模試モード(要件1・2)はログイン不要に変更した。ログインが必須なのは、演習履歴を長期的にアカウントへ紐づける必要がある復習ノート(要件3)・スコアダッシュボード(要件4)のみとする
   - Acceptance criteria:
     - [ ] ユーザーはGoogleアカウントでログインできる
     - [ ] ログイン状態で演習履歴・誤答ノートが永続化される

### Nice-to-Have (P1)
- 学習履歴の推移グラフ(週次・月次のスコア推移)
- 問題への難易度タグ・出題分野タグ、タグによる絞り込み
- 演習中のブックマーク機能(誤答以外にも後で見返したい問題を保存)
- 検索機能の拡充(キーワード検索など)

### Future Considerations (P2)
- **Listeningセクションの追加**: v1では音声合成(TTS)基盤の整備コストのため対象外とするが、将来的にListening問題(Part A/B/C相当)・音声ファイル・専用の演習/模試フローを追加する。v1の段階でセクションを疎結合に扱えるデータ・UI設計にしておくことで、追加時の手戻りを最小化する
- コミュニティ機能(問題に対するコメント・質問投稿)
- 語彙学習ツール(単語帳・単語テスト)
- 多言語UI対応
- 有料プラン・追加コンテンツ(将来的にマネタイズする場合の拡張余地として設計だけ意識)

## Success Metrics

### Leading Indicators
- 後輩を中心とした登録ユーザー数
- 週次アクティブ演習数(セクション別演習の実施回数)
- 模試モードの完了率(開始したうち最後まで通し受験した割合)

### Lagging Indicators
- 4週間後の再訪率(継続利用率)
- 後輩からの定性的フィードバック・満足度
- 実際にTOEFL ITPを受験した後輩からの自己申告スコア向上

### Targets(個人プロジェクトの初期目標として)
- 身近な後輩10〜20人に使ってもらい、そのうち70%以上が模試モードを1回以上完了する(公開後1ヶ月時点で評価)
- 継続利用率(4週間後再訪)30%以上を目安とする

## Timeline Considerations
- 明確な締め切りはなし(個人プロジェクト)
- v1スコープとして4つのP0機能(セクション別演習・模試モード・誤答ノート・スコア分析ダッシュボード)がすべて要求されているが、ソロ開発であることを踏まえ、以下の順序での段階的な内部開発を推奨する:
  1. セクション別演習 + 最低限のアカウント機能(後輩がまず使える最小状態)
  2. 誤答管理(復習ノート)
  3. 模試モード(タイマー・通し受験)
  4. スコア換算・弱点分析ダッシュボード
- ただし公開(v1リリース)は上記4機能が揃った時点とする
- v1公開後の拡張として、Listeningセクション(音声問題・TTS基盤の整備を含む)の追加を次フェーズで検討する
