# デザイン計画

`design-taste-frontend` スキルに基づき、実装着手前のデザイン方針をまとめたもの。PRD([toefl-itp-prd.md](./toefl-itp-prd.md))・エンジニアリングタスク([toefl-itp-engineering-tasks.md](./toefl-itp-engineering-tasks.md))を前提とする。

## Design Read

学習・演習アプリ(英語演習サイト。コンテンツ対象はTOEFL ITP)+ その入り口となるマーケティングLP。日本語話者の大学生(後輩)向けに、calm / academic / trustworthy な言語で、Tailwind v4 + shadcn/ui ベースの落ち着いたモダンな構成に寄せる。

## スコープの整理

`design-taste-frontend` はLP・ポートフォリオ・リデザイン向けのスキルで、ダッシュボードや高密度プロダクトUIは対象外と明記されている(スキルSection 13)。このプロジェクトは性質の異なる3領域を持つため、適用度を分ける。

| 領域 | スキル適用度 | 方針 |
|---|---|---|
| トップページ(未ログインLP) | フル適用 | 後輩に「使ってみたい」と思わせる、モダンで信頼感のある入り口 |
| 演習・模試・復習ノート・ダッシュボード(ログイン後) | 部分適用(本来スキルのスコープ外) | 派手な演出を避け、可読性・集中しやすさ・タイマーの視認性を最優先。色/フォントのトークンは共通、LP向けのレイアウト演出ルール(eyebrow制限、marqueeなど)は適用しない |
| 管理画面(問題管理) | 対象外 | 自分専用。shadcn/uiのデフォルトに近い実用本位、装飾ゼロ |

## Dial値

| コンテキスト | VARIANCE | MOTION | DENSITY | 理由 |
|---|---|---|---|---|
| LP | 6 | 4 | 3 | 官公庁的に硬くなりすぎず、煽らない。控えめな非対称性+最小限のスクロール演出 |
| 演習・模試(単問解答画面) | 3 | 2 | 3 | 制限時間付きの試験中に気を散らす演出は厳禁。長文読解の可読性を最優先 |
| 復習ノート・ダッシュボード(一覧系) | 3 | 2 | 5 | 情報量が多いため密度は上げるが、装飾的な演出は入れない |
| 管理画面 | 1 | 1 | 6 | 実用本位。shadcn/uiデフォルトのまま |

## デザインシステム / 技術選定

- **コンポーネント基盤**: Tailwind v4(導入済み)+ shadcn/ui(`npx shadcn@latest init`)。フォーム・RadioGroup(選択肢)・Tabs(復習ノートの絞り込み)・Dialog・Progress(タイマー)・Chart(Rechartsラッパー、スコアダッシュボード用)など、演習アプリに必須の部品をownできる形で導入する
- **アイコン**: `@phosphor-icons/react` に統一(1ファミリーのみ)。strokeWidth は 1.5 に統一
- **アニメーション**: `motion/react`。LPの `whileInView` 程度のエントランス演出に留め、演習・模試画面ではほぼ使わない(タイマー進行バーなど機能的なものを除く)
- **画像**: 画像生成ツールが利用できない環境のため、写真素材(ストックフォト的な「勉強する学生」等)に頼らない、タイポグラフィ+アクセントカラー中心のLPにする

## タイポグラフィ計画

UI言語は日本語のみ(PRD Non-Goals)だが、演習コンテンツ本体(Reading本文・選択肢)は英語のため、日英で役割の異なるフォントを使い分ける。`next/font/google` で必要な書字系・ウェイトのみをルートごとに読み込み、バンドルサイズを抑える。

| 用途 | フォント | 理由 |
|---|---|---|
| 日本語UI本文(ナビ・ボタン・説明文) | **Noto Sans JP** | 可読性・ヒンティングともに安定。学習ツールとしてクセを出しすぎない安全な選択 |
| 日本語見出し(LPのみ) | **Zen Kaku Gothic New**(Bold) | Noto Sans JPよりやや個性を出し、LPに「作り込まれている」印象を持たせる。アプリ側の見出しは集中を妨げないようNoto Sans JPに統一し、LPとの差を意図的につける |
| 英語長文(Reading本文) | **Literata** | Googleが電子書籍(Play Books)向けに画面読書用に設計したセリフ体。長時間の英文読解というこのアプリの核心機能に対して、根拠のある選定(スキルのSection 4.1で許容される「genuinely editorial / publication」の例外に該当) |
| 数字・タイマー・スコア | **Geist Mono** | 等幅なのでカウントダウン中に桁がガタつかない |
| 選択肢ラベル(A/B/C/D)・英語ボタンラベル | **Geist** | Geist Monoと同系統でペアが揃う |

**注意**: 演習・模試画面ではLiterataとGeist Monoのみを読み込み、Zen Kaku Gothic NewはLPのみで読み込む(ルート単位でフォント分割)。

## カラーパレット

ニュートラルベース(Zinc)+アクセント1色(ディープコバルト/インディゴ系の青)。AIっぽい紫グラデーションには寄せず、彩度を抑えて「集中できる信頼感」を出す。

| トークン | ライト | ダーク | 用途 |
|---|---|---|---|
| `--background` | `#FAFAFA`(zinc-50) | `#0A0A0B`(zinc-950近似、非純黒) | ページ背景 |
| `--surface` | `#FFFFFF` | `#151517` | カード・入力欄 |
| `--text-primary` | `#18181B`(zinc-900) | `#F4F4F5`(zinc-100) | 本文 |
| `--text-secondary` | `#71717A`(zinc-500) | `#A1A1AA`(zinc-400) | 補足テキスト |
| `--border` | `#E4E4E7`(zinc-200) | `#27272A`(zinc-800) | 罫線 |
| `--accent` | `#2E3E9E`(ディープコバルト) | `#5B6EE8`(コバルトを明度アップ) | CTA・リンク・選択状態。サイト全体でこの1色に固定 |
| `--success` | `#15803D`(green-700系) | `#4ADE80`(green-400系) | 正解フィードバック(意味的な色。アクセントの対象外) |
| `--danger` | `#B91C1C`(red-700系) | `#F87171`(red-400系) | 不正解フィードバック(同上) |

- ダークモードは **Tailwindの `dark:` バリアントでトークンを最初から定義**する。ただしトグルUIの実装(P1)は行わず、v1は `prefers-color-scheme` 追従のみとする(ユーザー決定事項)
- アクセントカラーはサイト全体(LP・アプリ・管理画面)で統一。セクション単位で別の色に切り替えない(Color Consistency Lock)
- 角丸は1スケールに統一(`rounded-lg` 相当)。ボタンのみpill(`rounded-full`)にする場合はその例外をこの1箇所にだけ明文化する

## LPのレイアウト方針(anti-slopルール適用)

- ヒーローは非対称構成。写真がないため、大きめのタイポグラフィ + アクセントカラーのグラフィック要素(色面・大きな数字のような視覚アンカー)で構成する「Editorial Manifesto Hero」寄りの型を採用
- ヒーローの文字要素は最大4つ(見出し・サブテキスト・CTA1つ+任意で1つ)。「後輩の学習のために作った」という個人プロジェクトらしい文脈は、ヒーロー直下の専用セクションで語る(ヒーロー内に詰め込まない)
- 機能紹介(セクション別演習・模試・復習ノート・スコア分析)は3列均等カードを避け、非対称なbentoグリッド(4項目→2+2や1+3などメリハリのある分割)にする
- 使い方セクションは「Step 1/2/3」ラベルを使わず、動詞そのもの(「セクションを選ぶ」「解く」「弱点を確認する」)をラベルにする
- eyebrow(見出し上の小さいラベル)は全セクション数の1/3以下に制限
- emダッシュ(—)は本文・見出し・ボタン・キャプションすべてで使用禁止
- セクションごとに異なるレイアウトファミリーを使い、image+text分割の連続は2回までに制限(このLPは基本的に画像を使わないため、色面+テキスト構成のバリエーションで代替する)

## アプリ側(演習・模試・復習ノート・ダッシュボード)の設計原則

スキルのLP向けルール(eyebrow制限・marquee・bento装飾など)は適用しない。代わりに以下を独自原則とする。

1. **試験中は演出ゼロ**: 模試モード・単問演習中はエントランスアニメーション・ホバー演出を最小限にし、正誤フィードバックの色変化とタイマーの進行のみに演出を絞る
2. **長文は読みやすさ最優先**: Reading本文はLiterata、行長は65ch程度に制限し、十分な行間(`leading-relaxed`)を確保
3. **タイマーは常に視認できる位置に固定**: スクロールしても見失わないようsticky配置
4. **復習ノート・ダッシュボードは高密度だがカード/リスト単位で区切る**: 10行以上のテーブルに `border-b` を全行につけるレイアウトは避け、カードグリッドまたはグルーピングされたセクションで表示する(スキルSection 4.9のガイドラインをアプリ側にも適用)
5. **正誤の色は意味的トークン(success/danger)のみ**: アクセントカラー(コバルト)を正誤表示に流用しない

## ページ一覧と設計方針

| ページ | 方針 |
|---|---|
| トップページ(LP) | 上記LP方針をフル適用。Googleログインへの単一CTA |
| セクション選択 | シンプルな選択UI(2択: Structure / Reading)。装飾最小限 |
| 演習(単問解答) | Literata本文、shadcn RadioGroupで選択肢、解答後に即時フィードバック |
| 模試モード | sticky タイマー(Geist Mono)、進行状況表示、離脱時の確認ダイアログ |
| 復習ノート | カードリスト、セクション/日付でのTabsフィルタ |
| スコア・弱点分析ダッシュボード | shadcn Chart(Recharts)でセクション別正答率を可視化。「公式スコアではない」注記を明示 |
| 管理画面(問題管理) | shadcn/uiのデフォルトテーブル+フォーム、装飾なし |

## 次のアクション

1. `shadcn/ui` の初期化(`npx shadcn@latest init`)とベースコンポーネントの追加
2. `next/font/google` でNoto Sans JP / Zen Kaku Gothic New / Literata / Geist / Geist Monoをルート単位で設定
3. Tailwind設定に上記カラートークンをCSS変数として定義(`globals.css` に `:root` と `.dark` を用意)
4. LPのワイヤーフレーム(セクション構成)をコードに落とし込む
