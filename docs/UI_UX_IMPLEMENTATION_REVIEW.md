#### [High] マークシート風ナビゲーターで「見直しフラグ」と「解答済み」が視覚的に区別できない
- 視点: Designer
- 対象: `web/src/components/mock-section-runner.tsx:118-140`
- 問題: セルの背景色は `isAnswered && !isFlagged` の場合のみ解答済み色になり、`isFlagged` が真だと解答済みかどうかに関わらず一律グレーになる。「フラグを立てたが未解答」と「フラグを立てて解答済み」が同じ見た目になる。
- 根拠: 該当箇所のclassName分岐ロジックが2条件排他的であることを確認済み(コード読解による確定事実)。
- 影響: 模試終了間際に「未解答が残っていないか」をグリッドで確認する行為は必須のワークフローだが、フラグ付き設問だけはこの確認ができず、誤認により未解答のまま提出、または解答済みなのに焦って再確認する等のリスクがある。
- 改善案: フラグは背景色ではなく別レイヤー(角のマーカー、下線、小さいアイコンオーバーレイ)で表現し、解答済み/未解答の背景色分岐とは独立させる。凡例(現状「■解答済み」「□未解答」の2状態のみ)にもフラグの説明を追加する。
- 確認方法: 1問に解答した上でフラグを立て、ナビゲーターが「解答済み」の見た目のままかを実機確認。

#### [High] ゲストの演習・模試履歴がログイン後に引き継がれない
- 視点: Engineer

- 確認方法: ゲストのまま模試を1回完了→ログイン→ダッシュボード/復習ノートに反映されないことを実機確認。

## 7. Conflicts and Trade-offs

- **見直しフラグの非永続化**(Medium): 実装側は「フラグは採点対象外の補助メモであり、解答そのもの(採点対象の進捗)はDB永続化されているためPRD要件は満たしている」という設計判断だった。Designerレビューは「ユーザー体験としてはフラグも進捗の一部であり、消えるのは望ましくない」と指摘。どちらの立場にも根拠があり、フラグ機能をどこまで「進捗」として扱うかはプロダクト判断が必要。
- **トップページ削除と商標免責表示**: 実装(削除)はユーザーとの合意に基づく意図的な決定であり、レビュー上の指摘事項ではない。ただし「ETSと非提携である」旨の免責表示自体は、LP以外の場所(共通フッター等)に軽量な形で残す価値があるかもしれない、という論点は独立して残る(Blockerではなく、任意の検討事項として記録するに留める)。
